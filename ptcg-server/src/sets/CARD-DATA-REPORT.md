# Card-data discrepancy report

Auto-generated by `ptcg-server/src/sets/check-card-data.ts --report`. It compares every
implemented card **stub** against its set's `card-data.json` (the pokemontcg.io source the
stubs should match). Cards are paired by **normalized name** (not collector number), so this
is immune to setNumber drift and naming conventions (LV.X / "-GX"↔"GX" / "Prism Star"↔"◇").
Each line is `field: <stub value> → should be <card-data value>`.

**How to read this:** two distinct causes produced these. Sets generated *at release* from
fetched data (SV-era) are mostly **one wrong attack name** per card (provisional English
localization); the data is otherwise correct. Sets **backfilled with no source data** (the
Jan-2026 "Implement complete X set" burst — BLW/EPO/NXD/NVI and similar) are wrong in many
fields per card because the cards were hallucinated from the *wrong printing* — those are
flagged ⚠️ severe below.

**Caveats:** gallery/promo subset cards (non-numeric numbers like `GG2`/`TG4`) are skipped —
`card-data.json` does not include those subsets, so it is a reference gap, not a bug. Naming
conventions (Star↔★, LV.X, Prism Star, "-GX"↔"GX") are normalized away. So the few remaining
`name-unpaired` rows are real: a typo, or a card placed at the wrong collector number /
invented by the no-source backfill. Attack damage compares the leading integer, so `20×`/
`120+` computed attacks are not flagged.
